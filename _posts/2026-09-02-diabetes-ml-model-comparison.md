오늘은 환자의 건강 정보를 이용해 1년 후 당뇨병 진행 정도를 예측하는 종합 실습을 진행했다. 목표는 단순히 예측값을 만드는 것이 아니라 다음 세 가지 질문에 답하는 것이었다.

1. 어떤 모델과 하이퍼파라미터가 Test MAPE를 가장 낮추는가?
2. 진행 정도가 가장 높거나 낮게 예측되는 환자 집단에는 어떤 규칙이 있는가?
3. Random Forest가 판단할 때 가장 중요한 변수는 무엇인가?

이번 데이터는 442개 관측치와 10개 입력 변수로 이루어진 작은 정형 데이터다. 이미지나 텍스트처럼 복잡한 비정형 데이터가 아니고 표본 수도 많지 않기 때문에, 딥러닝 신경망보다 트리 기반 머신러닝을 우선 비교하는 편이 적절하다고 판단했다.

## 1. 문제와 데이터 이해

목표 변수 `target`은 환자의 1년 후 당뇨병 진행 정도를 나타내는 연속형 수치다. 따라서 이 문제는 범주를 맞히는 분류가 아니라 숫자를 예측하는 **회귀 문제**다.

| 변수 | 의미 |
|:--|:--|
| `age` | 나이 |
| `sex` | 성별 |
| `bmi` | 체질량지수 |
| `bp` | 평균 혈압 |
| `s1` | 총 콜레스테롤 |
| `s2` | LDL |
| `s3` | HDL |
| `s4` | 총콜레스테롤/HDL 비율 |
| `s5` | 혈청 중성지방 |
| `s6` | 혈당 |

실습 조건에 따라 데이터 분할과 전처리 방법은 변경하지 않았다.

```text
전체 데이터 442건
  → Train/Test를 7:3으로 분할(random_state=42)
  → Train 중앙값을 기준으로 결측값 대체
  → Train을 기준으로 Min-Max Scaling
  → target은 변환하지 않음
```

Test 데이터가 전처리 기준 계산에 섞이지 않도록 중앙값과 스케일러를 Train에서만 학습한 뒤 Test에 적용했다. 이는 데이터 누수를 방지하기 위한 중요한 원칙이다.

## 2. 평가 지표: MAPE

모델 성능은 MAPE(Mean Absolute Percentage Error)로 비교했다.

```text
MAPE = 실제값 대비 절대 오차의 비율을 전체 데이터에서 평균한 값
```

MAPE는 낮을수록 좋다. 예를 들어 Test MAPE가 36.070%라면 테스트 데이터에서 예측값이 실제값과 평균적으로 약 36.070% 차이 났다는 뜻이다.

다만 MAPE는 실제값이 0 또는 0에 가까우면 값이 매우 커질 수 있다. 이번 데이터의 목표값은 양수 범위에 있어 계산할 수 있었지만, 실제 프로젝트에서는 MAE와 RMSE도 함께 확인하는 편이 안전하다.

## 3. 왜 딥러닝보다 머신러닝을 선택했나

딥러닝이 항상 머신러닝보다 성능이 좋은 것은 아니다. 이번 실습에서는 다음 이유로 트리 기반 모델을 선택했다.

- 데이터가 442건으로 작아 깊은 신경망이 과적합되기 쉽다.
- 입력이 10개의 수치형 변수로 구성된 정형 데이터다.
- 트리 기반 모델은 변수 간 비선형 관계와 상호작용을 잘 표현한다.
- Decision Tree 규칙과 Random Forest 중요도를 이용해 결과를 설명할 수 있다.
- 신경망보다 하이퍼파라미터 실험과 결과 해석이 비교적 간단하다.

딥러닝은 대규모 이미지, 음성, 자연어처럼 자동 특징 추출이 중요한 문제에서 강점이 크다. 반면 작은 표 형태 데이터에서는 Random Forest나 Boosting 모델이 더 안정적인 출발점이 되는 경우가 많다.

### 모델별로 예상한 결과

모델을 고를 때는 이름만 나열하지 않고 각 모델에서 기대하는 역할을 먼저 정했다.

- **Random Forest**는 여러 트리의 결과를 평균하므로 단일 Decision Tree보다 과적합과 예측 변동이 줄어들 것으로 예상했다.
- **Extra Trees**는 분할 기준에도 무작위성을 더하므로 Train 성능은 매우 좋아질 수 있지만, 작은 데이터에서는 Train과 Test의 차이가 커질 가능성도 있다고 봤다.
- **Gradient Boosting**은 앞선 트리의 잔차를 다음 트리가 보완하기 때문에 Random Forest보다 낮은 Test MAPE를 기대했다.
- **XGBoost와 LightGBM**은 학습률, 트리 수, 깊이와 규제를 함께 조절할 수 있어 작은 정형 데이터에서도 복잡한 비선형 관계를 안정적으로 찾을 가능성이 높다고 예상했다.

이 예상에 따라 Random Forest를 안정적인 기준점으로 두고, Extra Trees로 무작위성의 효과를 확인한 뒤 Boosting 계열 세 모델이 Test 오차를 얼마나 더 줄이는지 비교했다. 작은 데이터라는 점을 고려해 Boosting 모델의 트리 깊이는 낮게 제한하고, `learning_rate`를 낮추는 대신 `n_estimators`를 늘렸다. 한 번에 크게 수정하기보다 얕은 트리를 여러 번 더해 오차를 조금씩 보완하도록 한 것이다.

## 4. 다섯 가지 회귀 모델 비교

자동 최적화 도구는 사용하지 않고, 직접 정한 하이퍼파라미터로 Random Forest, Extra Trees, Gradient Boosting, XGBoost, LightGBM을 비교했다.

![회귀 모델별 Train/Test MAPE와 실행 시간 비교]({{ '/assets/images/diabetes-ml/01-model-comparison.png' | relative_url }})

| 순위 | 모델 | Train MAPE | Test MAPE | 실행 시간 |
|:--:|:--|--:|--:|--:|
| 1 | LightGBM | 26.014% | **36.070%** | 1.224초 |
| 2 | XGBoost | 29.364% | 36.382% | 0.645초 |
| 3 | Extra Trees | 13.089% | 37.089% | 1.664초 |
| 4 | Gradient Boosting | 29.585% | 37.309% | 1.584초 |
| 5 | Random Forest | 18.514% | 38.000% | 3.407초 |

최종 모델은 Test MAPE가 가장 낮은 **LightGBM**이었다. 주요 하이퍼파라미터는 다음과 같다.

```python
LGBMRegressor(
    n_estimators=500,
    learning_rate=0.02,
    num_leaves=7,
    max_depth=3,
    min_child_samples=15,
    subsample=0.8,
    colsample_bytree=0.8,
    reg_alpha=0.1,
    reg_lambda=1.0,
    random_state=42,
    n_jobs=-1,
    verbosity=-1
)
```

LightGBM과 XGBoost의 Test MAPE 차이는 0.312%p로 크지 않았다. 한 번의 Train/Test 분할만으로 LightGBM이 언제나 더 좋다고 일반화할 수는 없다. 실습에서는 Test MAPE 최소화가 목표였지만, 실제 모델 개발에서는 Train 내부에 Validation을 두거나 교차검증으로 후보를 선택하고 Test 데이터는 마지막에 한 번만 평가해야 한다.

### Train 성능만 보면 안 되는 이유

Extra Trees는 Train MAPE가 13.089%로 가장 낮았지만 Test MAPE는 37.089%였다. Train과 Test의 차이가 약 24%p로 크게 벌어졌다. 학습 데이터에는 매우 잘 맞았지만 새로운 데이터에 대한 일반화 성능은 LightGBM보다 낮았다.

이번 비교를 통해 모델 선택 기준은 가장 낮은 Train 오차가 아니라 **새로운 데이터에서의 오차여야 한다는 점**을 다시 확인했다.

예상과 실제 결과를 비교하면 Boosting 계열이 상위권을 차지할 것이라는 판단은 맞았다. LightGBM과 XGBoost가 각각 36.070%, 36.382%로 가장 낮은 Test MAPE를 기록했다. 반면 Extra Trees는 예상대로 Train MAPE가 가장 낮았지만 Test 성능에서는 3위에 머물렀다. 모델이 학습 데이터를 세밀하게 설명하는 능력과 새로운 데이터를 안정적으로 예측하는 능력이 같지 않다는 점이 수치로 드러났다.

## 5. 깊이 3의 의사결정나무로 규칙 설명하기

예측 성능이 가장 좋은 모델은 LightGBM이었지만, 여러 트리가 결합된 구조라 전체 판단 과정을 하나의 규칙으로 설명하기 어렵다. 그래서 별도의 `max_depth=3` Decision Tree를 학습해 진행 정도가 가장 높은 집단과 낮은 집단을 찾았다.

![당뇨병 진행도 집단을 설명하는 깊이 3의 Decision Tree]({{ '/assets/images/diabetes-ml/02-decision-tree-rules.png' | relative_url }})

### 진행 정도가 가장 높은 집단

```text
bmi > 0.377
AND bmi > 0.649
AND s2 <= 0.424
```

같은 변수의 조건을 논리적으로 정리하면 다음과 같다.

```text
bmi > 0.649 AND s2 <= 0.424
```

이 집단은 Train 데이터 15건을 포함했고, 평균 예측값은 **293.667**로 가장 높았다.

### 진행 정도가 가장 낮은 집단

```text
bmi <= 0.377
AND s5 <= 0.496
AND s5 <= 0.257
```

조건을 간단히 정리하면 다음과 같다.

```text
bmi <= 0.377 AND s5 <= 0.257
```

이 집단은 Train 데이터 42건을 포함했고, 평균 예측값은 **78.952**로 가장 낮았다.

여기서 임계값은 원래 의료 단위가 아니라 Min-Max Scaling된 값이다. 또한 이 규칙은 인과관계를 증명하지 않는다. 이번 학습 데이터와 트리 설정을 간단하게 설명하는 경계로 해석해야 한다.

## 6. Random Forest 특성 중요도

Random Forest의 불순도 기반 Feature Importance를 계산한 결과 상위 변수는 다음과 같았다.

![Random Forest 특성 중요도]({{ '/assets/images/diabetes-ml/03-random-forest-feature-importance.png' | relative_url }})

| 순위 | 변수 | 중요도 | 의미 |
|:--:|:--|--:|:--|
| 1 | `bmi` | 0.3669 | 체질량지수 |
| 2 | `s5` | 0.2013 | 혈청 중성지방 |
| 3 | `bp` | 0.1101 | 평균 혈압 |

`bmi`의 중요도가 약 36.7%로 가장 높았고, `s5`, `bp`가 뒤를 이었다. Decision Tree의 최고·최저 집단 규칙에서도 `bmi`가 첫 분기 변수로 나타났다는 점과 연결된다.

하지만 Feature Importance는 해당 변수가 질병 진행의 원인이라는 뜻이 아니다. 트리가 예측값을 나눌 때 상대적으로 많이 사용했다는 의미다. 변수들이 서로 상관되어 있으면 중요도가 한 변수에 몰리거나 여러 변수로 나뉠 수도 있다. 더 신뢰도 높은 설명이 필요하다면 Permutation Importance나 SHAP를 추가할 수 있다.

## 7. 오늘 배운 개념을 한 흐름으로 연결하기

오늘 다룬 머신러닝과 딥러닝의 주요 개념은 이번 실습 안에서 다음처럼 연결됐다.

```text
연속형 Target 확인
  → 회귀 문제로 정의
  → Train/Test 분리와 전처리
  → 여러 모델과 하이퍼파라미터 비교
  → Test MAPE로 최종 모델 선정
  → 얕은 Tree로 집단 규칙 설명
  → Random Forest로 중요 변수 확인
```

관련 개념도 함께 정리하면 다음과 같다.

- **지도학습**은 정답이 있으며, 범주형 Target은 분류, 연속형 Target은 회귀로 다룬다.
- **군집화**는 정답 없이 비슷한 관측치를 모으며, 군집 내 거리는 작고 군집 간 거리는 크도록 만든다.
- **앙상블**은 여러 모델을 결합해 단일 모델의 불안정성을 줄인다.
- **Random Forest**는 데이터와 변수를 무작위로 샘플링해 여러 트리를 만든다.
- **Boosting**은 앞선 모델의 오차를 다음 모델이 보완하며 학습한다.
- 모델이 학습 데이터에만 지나치게 맞으면 **과적합**이 발생한다.
- 딥러닝에서는 활성 함수가 비선형 표현력을 만들고, 오차 역전파로 가중치의 기울기를 계산한다.
- Dropout과 Early Stopping은 신경망의 과적합을 줄이는 대표적인 방법이다.

## 8. IMU 센서 고장 진단 경험과 연결해 보기

이번 실습에서 작은 데이터에 맞는 모델을 먼저 선택하고 변수의 의미를 함께 살핀 과정은 이전에 진행한 IMU 센서 고장 진단 프로젝트와 닮아 있었다.

당시 목표는 100초 이상의 데이터가 필요하던 진단 방식을 운용 단계에서 확보할 수 있는 **5초 데이터만으로 구현하는 것**이었다. 사용 구간을 95% 줄이면 빠른 진단이 가능해지지만, 모델이 확인할 수 있는 변화의 시간도 함께 줄어든다. 따라서 복잡한 모델을 먼저 적용하기보다 짧은 구간 안에 남아 있는 고장 신호를 어떤 변수로 드러낼지가 핵심이라고 판단했다.

300건의 데이터를 축별로 분석했을 때 단순 자세값만으로는 Drift의 변화 추세를 충분히 표현하기 어려웠다. 이에 다음과 같은 파생변수를 설계했다.

- 자세각의 시간에 따른 변화율
- 세 축의 각속도
- 5초 구간 내부의 기울기
- 축별 변화량과 추세를 나타내는 통계값

그다음 선형회귀와 5-Fold 교차검증을 사용해 축별 최적 변수 조합을 선택했다. 파생변수를 적용한 결과 단일 변수 모델보다 세 축의 RMSE를 평균 **92% 낮출 수 있었다.** 이 경험을 통해 데이터가 부족할수록 모델의 복잡도를 높이는 것보다 문제의 현상을 잘 표현하는 변수를 만드는 일이 더 중요할 수 있다는 점을 배웠다.

이번 당뇨병 실습에서는 전처리와 Feature Engineering 코드가 고정되어 있어 IMU 프로젝트처럼 새로운 파생변수를 추가할 수 없었다. 대신 같은 관점을 모델 선택과 결과 해석에 적용했다. 데이터가 442건에 불과하므로 신경망을 깊게 만드는 대신 얕은 트리를 누적하는 Boosting 모델을 선택했고, Decision Tree 규칙과 Random Forest 중요도를 통해 어떤 변수가 예측에 기여했는지 확인했다.

두 프로젝트에서 공통적으로 확인한 흐름은 다음과 같다.

```text
운영 조건과 데이터 한계 확인
  → 관측 가능한 신호에서 유효한 패턴 탐색
  → 데이터 크기에 맞는 모델 선택
  → 검증 데이터로 일반화 성능 확인
  → 변수와 규칙을 통해 결과 설명
```

IMU 프로젝트에서는 특징값 설계가 성능 개선의 중심이었고, 이번 실습에서는 트리 기반 모델과 하이퍼파라미터 선택이 중심이었다. 접근 방법은 달랐지만, 두 경우 모두 알고리즘을 먼저 정하기보다 데이터의 크기와 문제 구조를 먼저 이해해야 한다는 결론으로 이어졌다.

## 마무리

이번 실습에서는 작은 의료 정형 데이터의 특성을 고려해 딥러닝보다 트리 기반 머신러닝을 선택했다. 비교한 다섯 모델 중 LightGBM이 Test MAPE **36.070%**로 가장 좋은 결과를 보였다. 깊이 3의 Decision Tree에서는 높은 `bmi`와 특정 `s2` 조건을 가진 집단의 예측값이 가장 높았고, Random Forest에서는 `bmi`, `s5`, `bp`가 중요한 변수로 나타났다.

가장 크게 배운 점은 예측 성능과 설명 가능성을 하나의 모델에서 모두 해결할 필요는 없다는 것이다. LightGBM으로 성능을 확보하고, 얕은 Decision Tree와 Feature Importance로 결과를 설명하는 방식처럼 목적에 따라 모델의 역할을 나눌 수 있다. 여기에 IMU 프로젝트에서 경험한 것처럼 데이터의 한계를 보완하는 특징 설계까지 더해지면, 모델을 복잡하게 만드는 것만으로는 얻기 어려운 개선을 만들 수 있다.

다음에는 교차검증으로 모델 선택의 안정성을 확인하고, Permutation Importance와 SHAP를 이용해 변수 영향의 방향까지 분석해 보고 싶다.
